## 5. Desired Behavior
Required behavior:
- Jump actions resolve from named adapter actions, not catalog code.
- Metadata/assignment issues navigate to Audit Overview and focus the exact existing control.
- Source issues navigate to Sources and focus the relevant source control.
- Logic issues navigate to Logic Builder, select/reveal virtualized step by stable ID, then focus the target condition/action/join control.
- Display issues navigate to Display Fields and focus the owning control/row when present.
- Stale target falls back to owning page or disables Jump without mutating another item.
- Safe inline fixes validate active audit identity, step/condition target, supported option set, and current state immediately before mutation.
- Candidate safe fixes: audit name/purpose text only if existing mutation path can be reused; missing join type from existing supported join values; missing condition operator from current valid operators; missing action type from current valid action options.
- Assignment, source, field, relationship, hierarchy, deleted-reference, and ambiguous fixes remain navigation-only.
- Successful fix uses current commit path, invalidates relevant pages/issues, schedules existing autosave/durable write, re-evaluates canonical issues, and preserves predictable focus.
- Failed/stale fix makes no mutation and leaves an actionable message.
- Remove duplicate evaluator bodies/wrapper chains only after all callers point to the canonical result.
- Retain public validateAudit()/renderValidationPanel()/atlasLogicIssues names only as thin compatibility wrappers if active callers require them.
- Do not add a publication block. Critical issues remain prominent advisory results unless existing code already blocks publication.
Expected user flow: Open issue panel, select Jump or supported Fix, navigate/fix safely, see issue result update, persist through normal paths.
Source of truth: Current active audit and existing mutation options/commit functions.
Error behavior: Stale audit/target/action aborts with no mutation; one action failure does not close the panel or suppress other issues.
Required implementation: No action logic in JSON; no destructive automatic fix; no access to js/15-visual-ui-upgrades.js.

## 6. Acceptance Criteria
1. Every issue with canJump true navigates to its owning page and resolves the intended current target or safe fallback.
2. Off-screen Logic Builder targets are revealed by stable step ID before focus.
3. Supported fixes present only current valid choices and commit through existing mutation paths.
4. Stale or mismatched audit/target prevents mutation and shows an actionable error.
5. Assignment, source/field selection, relationship, hierarchy repair, and deleted-reference issues remain navigation-only unless unambiguous current evidence proves a safe fix.
6. Successful fix updates canonical issues and both UI surfaces while preserving autosave/durable-write behavior.
7. Parent-descendant action exception remains exact after navigation/fix integration.
8. Duplicate issue calculations are removed; remaining public validation functions are documented thin wrappers.
9. Publication, preview/export, Visual Picker, Join Picker, database/API/authorization, hierarchy, virtualization, and dependencies remain unchanged.
10. Documentation accurately describes final files, ownership, public functions, rule catalog, compatibility wrappers, and protected-file rule.
11. Final ZIP contains actual feature files and required generated/documentation artifacts only.
